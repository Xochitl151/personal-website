# 部署上手指南（GitHub + Cloudflare Pages）

> 前提：你已有 **GitHub 账号**，本机已装 **Git**。  
> 目标：免费上线作品集，简历/海投里贴链接即可。

---

## 先回答你的三个担心

### 1. 需要日常维护吗？

**几乎不用。**

| 情况 | 你要做什么 |
|------|------------|
| 网站内容不改 | **零维护**。站一直在，不用续费、不用开机、不用登录保活 |
| 改文案 / 加项目 / 换简历 | 改本地文件 → `git push` → Cloudflare **自动重新部署**（几分钟） |
| 域名、服务器、证书 | 免费档用 `*.pages.dev` 时 **都不用管** |

不是服务器那种「要自己运维」；是静态网页挂在 CDN 上，推代码才更新。

### 2. 这个方法能持续多久？

- Cloudflare Pages **免费档长期开放**，个人作品集用免费档是常规做法。
- 没有「试用 30 天到期」这类限制；只要平台政策还在，站就能一直开着。
- 政策偶尔会调（例如每月构建次数上限），但对「偶尔改改站」的个人站几乎无影响。
- **海投周期（几个月到一两年）完全够用**；很多人也长期挂着当作品集。

> 风险不是「免费突然到期」，而是：若某天平台大改规则，再换 Netlify / Vercel / GitHub Pages 即可（同一套 `dist` 静态站，迁移成本低）。

### 3. 最多几人访问？海投会不会超限？

对本站（纯静态 Astro，无后端函数）：

| 项目 | 免费档大致情况 | 海投够不够 |
|------|----------------|------------|
| 访问人数 / 流量 | 官方写 **静态资源请求与带宽 unlimited（不限）** | **绰绰有余** |
| 每月重新构建次数 | 约 **500 次/月** | 你一天改几次都够；正常改站一个月几次 |

海投场景：HR / 面试官点开链接，一天几十、几百次访问都算多；即便几千人点，对 Cloudflare 静态站也只是毛毛雨。

**结论：按「同时在线人数」也不用担心；免费档远超个人作品集需求。**

## 总体流程（你要做的事）

```
本机项目 → 推到 GitHub 仓库 → Cloudflare 连上仓库 → 自动构建 → 得到网址
```

你只需要做完下面 **A → B → C**，大约 **30～60 分钟**（含注册 Cloudflare、点页面）。

---

## A. 第一次：把项目推到 GitHub

### A1. 在 GitHub 新建空仓库

1. 打开 [https://github.com/new](https://github.com/new)
2. **Repository name**：例如 `personal-website`（随意，好记即可）
3. 选 **Public**（作品集公开更方便；私有也可，Cloudflare 仍能部署）
4. **不要**勾选 “Add a README” / “Add .gitignore” / “Choose a license”（保持空仓库，避免第一次推送冲突）
5. 点 **Create repository**
6. 页面上会显示仓库地址，形如：  
   `https://github.com/你的用户名/personal-website.git`  
   **复制下来**，后面要用。

### A2. 本机打开项目目录，初始化并推送

在 Cursor / VS Code 终端，或 PowerShell，进入项目根目录（有 `package.json` 的那一层）：

```powershell
cd "d:\AAA project\Personal Website"
```

确认本机 Git 可用：

```powershell
git --version
```

然后执行（**把下面的仓库 URL 换成你的**）：

```powershell
git init
git add .
git commit -m "init: astro portfolio site"
git branch -M main
git remote add origin https://github.com/你的用户名/personal-website.git
git push -u origin main
```

#### 若 `git push` 要求登录

- 浏览器弹窗登录 GitHub，或  
- 使用 **Personal Access Token** 当密码（GitHub 已不支持用账户密码直接 push）  
- 或本机已配好 GitHub Desktop / SSH，按你平时习惯即可  

推送成功后：浏览器打开仓库页，应能看到项目文件。

#### 常见报错

| 现象 | 处理 |
|------|------|
| `remote origin already exists` | 说明以前加过远程：用 `git remote set-url origin <你的URL>` 再 `git push -u origin main` |
| `failed to push` / 认证失败 | 重新登录 GitHub，或换 HTTPS + Token |
| 仓库里已有 README，拒绝非快进 | 空仓库最省事；若已有文件，可先在网页删掉 README 再推，或按 GitHub 提示 `pull` 后再 `push` |

---

## B. 注册 Cloudflare 并连接仓库（真正上线）

### B1. 注册 / 登录 Cloudflare

1. 打开 [https://dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up)
2. 用邮箱注册（可用与 GitHub 相同的邮箱）
3. 验证邮箱后进入控制台  

> 免费账号即可，**不必绑信用卡**（若页面推销付费计划，选 Free / 跳过即可）。

### B2. 创建 Pages 项目

1. 左侧进 **Workers & Pages**（有的界面叫 **Compute (Workers)** → Pages）
2. **Create** → 选 **Pages** → **Connect to Git**
3. 授权 Cloudflare 访问你的 GitHub（按提示点 Authorize）
4. 选中刚才的仓库 `personal-website`（或你起的名字）

### B3. 构建设置（照抄）

| 项 | 填什么 |
|----|--------|
| Framework preset | **Astro**（有就选；没有也行） |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | 留空（默认仓库根目录） |

**环境变量**（很重要，避免 Node 版本不对）：

- 变量名：`NODE_VERSION`
- 值：`22`

然后点 **Save and Deploy** / **开始部署**。

### B4. 等构建完成

- 通常 **2～5 分钟**
- 成功后会出现地址，类似：  
  `https://personal-website-xxxx.pages.dev`  
  或 `https://你起的项目名.pages.dev`

在手机流量下打开检查：

- [ ] 首页  
- [ ] `/tour`  
- [ ] 两个项目页  
- [ ] `/pitch/data` 或 `/pitch/ai`（按你投的方向）  
- [ ] 简历能否下载（若已放 `public/files/resume.pdf`）

把这个 **完整 https 链接** 写进简历、海投系统、邮件签名。

## C. 上线后你偶尔要做的事

### C1. 改网站内容后如何更新？

本地改完 → 再推一次 GitHub：

```powershell
cd "d:\AAA project\Personal Website"
git add .
git commit -m "update: 说明改了什么"
git push
```

Cloudflare 会自动重新构建；几分钟后线上就是新版本。  
**不用**再去 Cloudflare 点一遍创建项目。

### C2. 把占位域名改成真实地址（可选但建议）

打开项目里的 `astro.config.mjs`，把：

```js
site: 'https://example.pages.dev',
```

改成你真实的 Pages 地址，例如：

```js
site: 'https://你的项目名.pages.dev',
```

同时改 `public/robots.txt` 最后一行的 Sitemap 地址（同一域名）。

然后 `git add` → `commit` → `push`。  
这会影响 canonical 等 SEO 相关字段；作品集也建议改准。

### C3. 换简历 PDF

1. 用新 PDF 覆盖 `public/files/resume.pdf`（或按仓库实际路径）  
2. `git push`  
3. 等部署完成；简历链接不变，内容已更新  

### C4. 要不要买域名？

| 选择 | 说明 |
|------|------|
| **先不用** | 直接用 `xxx.pages.dev` 海投完全可以 |
| 以后再买 | 在 Cloudflare 里给 Pages 绑自定义域名即可（域名本身通常要年费，托管仍免费） |

## D. 上线前检查清单（投递前勾一遍）

- [ ] GitHub 仓库已有完整代码  
- [ ] Cloudflare Pages 构建成功（绿色 / Success）  
- [ ] 手机流量能打开全站关键页  
- [ ] `astro.config.mjs` 的 `site` 已改成真实网址  
- [ ] 简历 PDF 是定稿，且里面的作品集链接与线上一致  
- [ ] 简历 / 海投表格里写的是 **https://...** 完整链接（不要漏 `https://`）

## E. 备选（出问题再看，平时不用）

| 平台 | 何时用 |
|------|--------|
| **Netlify** | Cloudflare 注册/构建不顺时；Build：`npm run build`，Publish：`dist`，Node 22 |
| **Vercel** | 同上，选 Astro 预设即可 |
| **GitHub Pages** | 只想用 GitHub、不想注册 Cloudflare；配置比 Pages 多一步，本站优先 Cloudflare |

本站是静态输出，换平台一般只是「换一个连 GitHub 的按钮」，代码不用推倒重来。

## F. 一句话总结

| 问题 | 答案 |
|------|------|
| 还要注册什么？ | **Cloudflare 免费账号**（GitHub、Git 你已有） |
| 要维护吗？ | **平常不用**；改内容再 `git push` |
| 能用多久？ | **免费档长期可用**，够海投与后续作品集 |
| 几人访问？ | 静态站免费档 **不限访问量级远超海投**；不用担心同时在线人数 |
