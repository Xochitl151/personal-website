# 互动展示构思（先想再做）

> 你的问题很对：**语雀/Notion 也能贴 Markdown + 图**，那自建站的价值在哪？  
> 答案不在「能写字」，而在 **帮面试官 30 秒内看懂、3 分钟内愿意往下点**——用结构和轻互动，不是堆功能。

---

## 1. 文档站 vs 你的站

| | 语雀/Notion | 你的 Astro 站（现在 + 可做） |
|--|-------------|------------------------------|
| 发链接 | ✅ | ✅ |
| 贴图贴字 | ✅ | ✅ |
| **固定叙事路径**（先结论再证据） | 靠读者自己翻 | ✅ takeaway + metrics + 目录 |
| **图表放大、读图** | 一般 | ✅ 已有 lightbox |
| **按岗位换视角** | 难 | 🔜 可做 |
| **可演示的小交互**（筛选/步骤） | 几乎不行 | 🔜 核心差异 |
| 域名 + 专业感 + 和简历一体 | 弱 | ✅ |

**一句话定位**：不是「另一个文档」，而是 **可浏览的分析案例页**——像产品经理给业务讲复盘，不像论文附件。

---

## 2. 面试官真正需要什么

HR / 业务面试官（非技术面）：

- 30 秒：**你做了什么、有没有结果**  
- 2 分钟：**图证明什么、你怎么想**  
- 不会翻 5000 字，也不会点开 zip

技术面：

- 口径、工具、边界 case（PDF 抽表失败怎么处理）  
- 最好 **能点到代码/流程**，但不用全贴

所以互动要服务：**省他们的脑力**，不是炫技。

---

## 3. 建议方向（分三期，后面再动手）

### 第一期 · 已有 + 小改（低成本，专业）

**泰迪杯页已补 5 张分析图 + 2 张获奖证明。**

还可做（仍不算大工程）：

1. **每张图下面固定三行「读图卡」**（写进 md 即可）  
   - 这图说明什么  
   - 不说明什么  
   - 若在实际业务里下一步怎么验证  

2. **顶部「分析链路」一条线**（静态即可）  
   `PDF → 抽取 → 清洗 → 可视化 → 选品筛选`  
   点击跳到对应章节（锚点，你站已有目录）

3. **结论前置**（已有 takeaway + metrics，保持）

→ 文档站做不到这么 **贴图的叙事**，除非人工排版很久；你是 **模板化复用到三个项目**。

---

### 第二期 · 轻互动（差异化，推荐优先做在泰迪杯）

适合特医项目，材料齐：

| 功能 | 面试官感受 | 实现思路（以后） |
|------|------------|----------------|
| **步骤条** | 「原来她是一步步做的」 | 任务 1.1→1.4→2.x→3.1，点一步展开 2～3 句 + 可选图 |
| **图库 Tab** | 不用滚很长 | 「流程 / 图表 / 证书」三个 Tab |
| **选品演示** | 「能落地」 | 用脱敏后的 `result2` 前几行做 **静态 JSON**，两个下拉（人群/症状）过滤表格——**假交互，真数据** |
| **岗位视角切换** | 投数据 vs 投产品都能看 | 同页两套 3 句摘要：数据岗强调口径工具；产品岗强调发现与建议 |

不做登录、不做后端；全是静态页 + 少量 JS。

---

### 第三期 · 可选加分（有时间再做）

- 实习项目：**行为漏斗示意**（静态 SVG，标注你分析的步骤）  
- 电商练习：**漏斗数字可切换渠道**（一组 JSON）  
- 全站：**「给面试官」60 秒导览页** `/tour`——三个项目各一张卡片 + 口述链接到 `面试背诵.md` 的摘要（网页版，不是让人读 md）

---

## 4. 不建议做的（避免优势变负担）

- 复杂动画、3D、首屏大视频  
- 把 notebook 全文嵌进网页  
- 为了互动而互动（小游戏、无意义 slider）  
- 和简历矛盾的「实时数据」  

---

## 5. 和「文档站」的总结句（你可写进自述）

> 我把项目做成 **可点的分析案例**，不是堆 PDF。  
> 每个项目：**结论 → 链路 → 图表读法 → 局限**；  
> 泰迪杯额外可以用 **选品筛选** 展示从 PDF 到决策的闭环。
