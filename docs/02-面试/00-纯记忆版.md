## 必问题 · 第一梯队（优先背）

### ① 3800+ 是什么数据？

**来源：** 实习内网用户业务数据（套餐、开通、地区等），SQL 提取后清洗。  
**字段：** 套餐类型、开通状态、地区等（表名可面试后说明）。  
**清洗：** Python（Pandas）+ Excel —— 缺失/异常、字段校验、口径统一。  
**目的：** 看用户结构与开通分布，做报表/看板，给业务跟踪。  
**别混：** 作品集用户分析页用的是 **IBM Telco 公开集**（约 7043 行），演示方法；**不是** 这 3800+ 原表。

**背一句：**  
「3800+ 是实习里用户套餐相关数据清洗后的有效规模；网站看板用公开电信客户数据做同类型演示，公司原表不外传。」

---

### ② 套餐 / 开通分析发现了什么？

**完整案例（公开集口径；实习用同类讲法，勿把公开集数字说成公司实数）：**

1. **发现：** 月付套餐用户最多，但在网率低于一年/两年合约。  
2. **解读：** 数据表现可能反映短合约用户更易流失，**不说**「用户不喜欢」。  
3. **建议：** 关注短合约续约与开通引导，用下一周期内网数据验证。

**背一句：**  
「公开集上月付在网率偏低；实习里我会按公司套餐口径做同样对比，建议业务核对开通/续约后再看下周期。」

---

### ③ 看板指标 · 为什么选这些？

| 指标 | 作用 |
|------|------|
| 套餐/合同分布 | 看用户结构 |
| 在网率（或开通率） | 看是否留在网内 / 开通结果 |
| 业务类型 / 地区 | 公开集看互联网业务；地区以实习内网为准 |

**背一句：**  
「套餐看结构，在网率看结果；地区是实习内网维度，公开页用业务类型视图代替。」

### ④ SQL 有没有 JOIN？

**有。** 逻辑示例：用户主数据与开通/套餐相关表按用户或业务键关联，再按套餐、地区聚合。细清洗多在 Python/Excel。

**背一句：**  
「会做多表关联，把套餐、开通、地区落到一张可分析表，再聚合统计。」
